stellar-ink 星墨 · 写作社区

一个写作社区：文章、笔记、评论、流星、回声、友链和写作统计。前端是 Vue 3 单页应用， 后端是三个 Java 进程——网关、用户服务、内容服务，在 Nacos 上注册与取配置， 由 Docker Compose 起在一台机器上。

  • 网关按路径和角色鉴权；登出与改密把令牌摘要写进 Redis 撤销列表，路由前拦截。
  • 缓存键是「命名空间版本 + 参数指纹」，写入后推进版本，旧参数组合立刻不可达。
  • Nginx 前置：登录 10 次/分、公开写接口 6 次/分、其余 API 50 次/秒，静态资源缓存 30 天。

RepoSleuth 多 Agent 代码侦探

给它一个仓库链接，或者一句「帮我找一个处理 PDF 的 Python 库」；它自己检索、clone、精读， 最后交出 mermaid 架构图、新人上手路线和风险清单。也能当 MCP Server 挂进 Claude 或 Cursor。

  • Scout 先选库，三个分析 Agent 并行：画结构、看可读性、挑风险，最后由 Chief 汇总。
  • LangGraph 状态机编排；检索排序 Top1 达到阈值才自动选定，否则把候选交给人确认。
  • 测试用假模型加两个真实仓库做基线，不联网、不烧 token 也能跑。
看四个 Agent 怎么分工

在做的两件事

一是把微服务从「能跑」推到「能运维」：鉴权放在哪一层做、缓存什么时候该失效、 限流压在 Nginx 还是网关、配置怎么下发、登出之后令牌凭什么立刻作废。 stellar-ink 就是这些问题的草稿纸，代码和取舍都写在仓库里。

二是 Agent 工程：怎么让模型少编、多查证，怎么把中间过程做成看得见的事件流。 RepoSleuth 是我目前的答案——它不假装一次读完整个仓库， 而是先检索、再精读、最后把不确定的地方标出来交给人。

两边用的是同一套习惯：先画清楚边界，再写代码；能落到文档里的决定，不留在脑子里。
