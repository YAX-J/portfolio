它是什么

星墨是一个写作社区。作者发文章、记私有笔记、写流星备忘录、丢回声漂流瓶；读者浏览、评论、加友链。 仓库里同时放着前端 stellar-ink-web、后端 stellar-ink-server、部署配置 deploy/、 接口与架构文档 docs/，以及一份 AI 编排模块的方案 stellar-ink-ai（还没实现）。

后端拆得不复杂：一个网关、两个业务服务，共用一个 MySQL 库和一个 Redis。复杂度不在服务数量， 在鉴权放在哪一层、缓存怎么失效、私有内容怎么隔离。

系统结构

几个关键决定

把服务收敛成两个边界 / 运行单元

最初的拆法更碎：流星、回声、友链各占一个服务。后来把它们并进 content-service。 原因很实际：这些服务各自只有一个控制器、一个 Mapper 和一个实体， 独立 JVM、连接池、熔断配置的成本高于隔离带来的收益；写作统计要读文章数据， 独立服务还得多一次远程调用和一个故障点。

合并的是运行单元，不是领域边界：content-service 内部仍按 post、note、comment、 meteor、echo、link、stats 分包。文档里也写明了重新拆分的门槛——要独立扩缩容、独立库、 独立发布节奏，或者有明确的团队归属，而不是「表不一样」。

关掉 discovery locator，只留显式路由网关 / 攻击面

Spring Cloud Gateway 默认可以把 /{serviceId}/** 转发到对应服务，配起来省事， 但也给了一条绕过网关鉴权的路。这里把它关掉，路由表只有手写的几条； /internal/** 不对外暴露。网关只做第一层校验：验签、按路径和角色放行。

JWT 不查库，但登出要立刻生效鉴权 / Redis

令牌由 user-service 签发，网关和两个业务服务用同一把密钥验签，所以鉴权不查库。 问题在登出：无状态 JWT 在过期前一直有效。做法是把当前令牌的 SHA-256 摘要写进 Redis 撤销列表，键跟着令牌一起过期；网关在路由前用响应式 Redis 统一查一次。

安全状态不放行：普通缓存读不到可以回源 MySQL，撤销列表读不到不能当没这回事。

缓存键带版本号，写完整片失效缓存 / 一致性

列表接口的参数组合太多，逐个删键不现实。做法是用「命名空间版本 + 参数指纹」拼键： 内容写入后原子推进版本号，所有旧参数组合立刻不可达。TTL 按热度分 30 秒、1 分钟、5 分钟； Redis 不可用时回源 MySQL 并熔断 30 秒，避免一挂就把数据库打穿。

私有笔记：对谁都回 404权限 / 内容隔离

网关对所有 GET 放行，PRIVATE 笔记能不能读由 content-service 判断：非作者一律 404， ADMIN 也读不了别人的私有笔记。归属判定比文章更严——只有作者本人能改、能删。 复核状态不落新列，由 verified_at 按 180 天实时派生。

一次请求要过哪几道

  • Nginx：静态资源直接返回；/auth、/user、/posts 等前缀反代到网关，顺手做限流。
  • Gateway：验签、查撤销列表、按路径与角色放行；/uploads/** 只读、可匿名。
  • 业务服务：AuthHelper 复核身份与角色，再进业务逻辑。
  • 数据层：MyBatis-Plus 读写 MySQL；公开读走 Redis，写入后推进缓存版本。

部署与运维

  • docker compose 起 Nginx、网关和两个业务服务；MySQL、Redis、Nacos 复用宿主机已有实例。
  • 80 端口只留健康检查与跳转，443 用 Cloudflare 源站证书终止 TLS，源站只放行 Cloudflare 网段。
  • 静态资源 30 天不可变缓存；SPA 刷新按 GET + Accept: text/html 回退 index.html， 避免和 /notes、/links、/search 这些与 API 前缀同名的前端路由打架。
  • 请求带 TraceId 贯穿三层；三个服务都开 Actuator 健康检查，Redis 断开会显示 DOWN。

还没做完的部分

AI 编排模块（stellar-ink-ai）目前只有方案，没有进 Maven 模块，也没进 Compose 编排。 头像存储有本地磁盘和腾讯 COS 两种实现：本地模式要求文件和数据库同机可达， 多实例部署会踩「上传成功但图片 404」，生产建议切对象存储。 Redis 限流与分布式锁还没做，现在的限流压在 Nginx 上。
